# CakeToHome ERP — Complete System-Wide Audit Architecture & Verification Strategy
## Candidate a001: Expert Panel + Test-First Acceptance + Explicit Trade-Offs

### 1. Expert Panel Perspectives & Synthesis
- **Lead ERP Architect Perspective:** The audit must verify that business domain invariants hold end-to-end across all modules (Order, Inventory, Billing, Teller, Accounting, Corporate). Bypassing domain services via direct DB or UI state is prohibited. The system must adhere to Clean Architecture: Browser -> API -> Domain Service -> Repository -> PostgreSQL.
- **Security Tester & Auditor Perspective:** Every route, API, and status transition must be validated against unauthorized vertical/horizontal escalation. We must test unauthenticated rejections, branch isolation (HTTP 403), role spoofing, parameter tampering, and BOLA/IDOR across customer, delivery partner, branch manager, and admin scopes.
- **QA & Browser Automation Director Perspective:** UI buttons cannot be assumed functional merely because they render. Real Playwright/Chromium execution is mandatory across Desktop (1920x1080), Tablet (768x1024), and Mobile (375x667). Form submissions, table pagination, filter resets, modals, and error boundaries must be tested with network and console logging.
- **Expert Synthesis:** A unified, traceable matrix linking each Module -> Feature -> Route -> API -> Allowed/Denied Roles -> Preconditions & State Transitions -> DB Entities -> Test ID -> Status -> Evidence.

### 2. Test-First Acceptance Criteria & Verification Gates
1. **Gate 1: Repository & Build Baseline:**
   - Git working tree must be strictly clean with zero uncommitted deletions.
   - Frontend TypeScript (`npx tsc --noEmit`) must compile with 0 errors.
   - Backend TypeScript must compile with 0 errors.
2. **Gate 2: Role-to-Feature Authentication & Authorization:**
   - Super Admin: Full platform governance, fiscal lock, system config, master accounting.
   - Internal Admin & Finance: Maker-checker-poster segregation of duties (SoD), AR/AP aging, BRS.
   - Branch Manager: Drawer shift management, physical cash count acknowledgement, overdraft guard.
   - Branch Staff: Bakery readiness, order fulfillment, stock movement.
   - Customer: Catalog browsing, address selection, cart validation, Razorpay mock payment, order tracking.
   - Delivery Partner: Task acceptance, OTP/proof of delivery, COD collection, shift remittance.
   - Planner/Dispatcher: Order batching, delivery slot capacity, zone assignment.
3. **Gate 3: PostgreSQL Authoritative State & Ledger Equilibrium:**
   - Double-entry balance: Total Debits == Total Credits == ₹14,925.00 across all 21 posted journals.
   - Preserved accounts: 1111 (+₹4,675.00), 1114 (-₹200.00), 1122 (-₹2,450.00), 1121 (+₹2,000.00), prototype invoices 31-35. Zero unauthorized adjustments.
4. **Gate 4: Playwright Multi-Device Coverage:**
   - Real browser interactions against Next.js (Port 3001), asserting zero uncaught exceptions, 200/201 API status codes, and persistent state reload.

### 3. Explicit Trade-Offs & Decisions
- **Trade-off A: Live Database Execution vs. Destruction Risk.** We prioritize safety: use read-only queries for historical audits and atomic rollback transactions for test simulations. Zero destructive re-seeding or migration resets.
- **Trade-off B: Complete Discovery vs. Phase-Specific Focus.** We execute an exhaustive discovery of all 23+ subdirectories, 57+ API endpoints, and all frontend routes across roles, ensuring no difficult or obscure areas are omitted.
- **Trade-off C: Deployment Restriction.** Production deploy remains strictly `BLOCKED` awaiting written Finance Controller authorization.
