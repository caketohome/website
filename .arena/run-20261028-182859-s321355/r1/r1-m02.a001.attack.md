ATTACK 1 [MAJOR] Hard Deletion Fails to Account for Historical Test Invoices
Where: "Step 3.2: Synthetic Product Purge -> DELETE FROM product WHERE title ILIKE '%TEST%' ..."
Problem: If a test cake was ever included in an invoice line or allocation log during Phase C testing (e.g. `invoice_allocation_log`), an unconditional hard delete could fail due to foreign key constraints or, worse, leave invoices referencing non-existent product IDs. The plan should prioritize a defensive soft-delete (`deleted_at = NOW()`, `is_active = false`), which cleanly removes the product from customer storefront queries without any risk to relational integrity.

ATTACK 2 [MINOR] Omission of Rollback Verification Script
Where: "Step 3.1: Table Classification & Safe Drop"
Problem: While the plan mentions that backups exist, it does not provide an automated rollback script to recreate dropped tables or restore table schemas if an unexpected downstream application dependency is discovered.
