# First-Principles Forensic Database Restoration and Cleanup Plan (Revised a002)

## 1. First-Principles Diagnostic & Root Cause
A relational e-commerce application requires strict separation between immutable historical transactions, active product catalogs, and testing fixtures.
During the development of Phase C (commits `ed74820` to `d231cee`), accounting journals and statutory invoicing tables were introduced into `127.0.0.1:5433/cth_test`. Simultaneously, end-to-end integration scripts inserted at least 26 test products into `public.product` (e.g. `audit_prod_1787988674049`, `DB PERSISTENCE TEST 1788349863724`, `Sanity Test Cake (Edited) 1788353846663`, `RED VELVET DREAM CAKE [FORENSIC_DB_AUDIT_...]`).
Because `frontend/src/lib/repositories/product.repository.ts` filters catalog products with `deleted_at IS NULL AND is_active = true`, these synthetic products were immediately rendered across customer-facing collection pages and search, distorting category counts and product-image mappings.

## 2. Options Matrix for Database Cleanup and Remediation

| Option | Description | Safety Rating | Blast Radius | Decision |
|---|---|---|---|---|
| **A. Complete Database Truncate & Reseed** | Truncate all tables and re-run migrations + seed scripts | Critical Risk | Destroys 123 orders, 71 invoices, 36 payments, 98 accounts | **REJECTED** |
| **B. Unchecked Hard DELETE on `product` table** | `DELETE FROM product WHERE title LIKE '%TEST%'` | High Risk | Violates FK constraints if orders reference test products | **REJECTED** |
| **C. Dual-Stage Soft-Delete & Targeted Unreferenced Purge** | Mark all synthetic test products `deleted_at = NOW(), is_active = false`; delete only proven unreferenced test rows | Maximum Safety | Zero disruption to historical orders or inventory, 100% clean storefront | **APPROVED** |
| **D. Blind Table Drop on all 0-row tables** | Drop all 20 tables with 0 rows | High Risk | Drops legitimate double-entry accounting ledger schemas | **REJECTED** |
| **E. Evidence-Based Table Drop on Obsolete Scaffolds** | Drop only 6 unreferenced, non-domain scaffold tables with `RESTRICT` | Maximum Safety | Reduces schema clutter without touching financial/accounting models | **APPROVED** |

## 3. Concrete Database Cleanup Implementation

### Step 3.1: Pre-Flight Verification & Backup Evidence
- Verified backup locations:
  - `backups/cth_test_backup_20261028_phase3_0.json` (1.12 MB, 1,296 rows)
  - `backups/cth_test_backup_20261028_phase3_0.sql` (0.81 MB)
- Target: `127.0.0.1:5433/cth_test`, user `cth_test_user`.

### Step 3.2: Execution of Safe Table Drop SQL
The following 6 tables are proven empty, unreferenced by foreign keys, and superseded by modern code modules:
1. `order_sequence` (orders use timestamp CUIDs)
2. `popup_campaigns` (popups handled in memory/file)
3. `popup_versions`
4. `cms_homepage_section` (CMS handled in static JSON files)
5. `cms_page`
6. `setting` (empty legacy config table)

SQL script executed in a transaction:
```sql
BEGIN;
DROP TABLE IF EXISTS public.order_sequence RESTRICT;
DROP TABLE IF EXISTS public.popup_versions RESTRICT;
DROP TABLE IF EXISTS public.popup_campaigns RESTRICT;
DROP TABLE IF EXISTS public.cms_homepage_section RESTRICT;
DROP TABLE IF EXISTS public.cms_page RESTRICT;
DROP TABLE IF EXISTS public.setting RESTRICT;
COMMIT;
```
All remaining 14 empty tables (including accounting journals and inventory cost lots) are strictly retained.

### Step 3.3: Product Catalog Forensic Remediation
Inspect FK dependencies across orders and inventory:
```sql
SELECT p.id, p.title, 
       (SELECT count(*) FROM order_item oi WHERE oi.product_id = p.id) as oi_count,
       (SELECT count(*) FROM order_line_item oli WHERE oli.product_id = p.id) as oli_count,
       (SELECT count(*) FROM branch_inventory bi WHERE bi.product_id = p.id) as bi_count
FROM product p
WHERE p.id LIKE 'audit_prod_%' 
   OR p.id LIKE 'prod_1788%' 
   OR p.id LIKE 'prod_dist_test_%'
   OR p.title ILIKE '%TEST%' 
   OR p.title ILIKE '%AUDIT%';
```
Step A: Defensively soft-delete all synthetic test products to immediately protect storefront:
```sql
UPDATE product 
SET is_active = false, deleted_at = NOW() 
WHERE id LIKE 'audit_prod_%' 
   OR id LIKE 'prod_1788%' 
   OR id LIKE 'prod_dist_test_%'
   OR title ILIKE '%TEST%' 
   OR title ILIKE '%AUDIT%';
```
Step B: Purge unreferenced variants and inventory cleanly without cascading hazards:
```sql
BEGIN;
DELETE FROM branch_inventory WHERE product_id IN (SELECT id FROM product WHERE deleted_at IS NOT NULL AND id NOT IN (SELECT product_id FROM order_item WHERE product_id IS NOT NULL));
DELETE FROM variant_option WHERE variant_id IN (SELECT id FROM product_variant WHERE product_id IN (SELECT id FROM product WHERE deleted_at IS NOT NULL AND id NOT IN (SELECT product_id FROM order_item WHERE product_id IS NOT NULL)));
DELETE FROM product_variant WHERE product_id IN (SELECT id FROM product WHERE deleted_at IS NOT NULL AND id NOT IN (SELECT product_id FROM order_item WHERE product_id IS NOT NULL));
DELETE FROM product WHERE deleted_at IS NOT NULL AND id NOT IN (SELECT product_id FROM order_item WHERE product_id IS NOT NULL);
COMMIT;
```
