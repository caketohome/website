## 1. Analogy: Telecom Signaling & Distributed Ledger Reconciliation
In telecommunications signaling (SS7/SIP) and ATM transaction networks, failures are categorized into three orthogonal layers:
1. **Routing Layer (404/SIP 404 Not Found)**: Root cause taxonomy:
   - *Type 1 (Route Shadowing)*: Catch-all routes intercepting specific sub-routes.
   - *Type 2 (Dynamic Segment Mismatches)*: Mismatched parameter names (e.g. `[slug]` vs `[id]`).
   - *Type 3 (Missing Route Handlers)*: UI links targeting routes without corresponding `page.tsx` or `route.ts`.
   - *Type 4 (Middleware Redirection Defect)*: Misconfigured route guards redirecting authorized roles to fallback routes.
2. **Session / Signaling Layer (RBAC/Controls)**: Two-phase commit state latches (UI intent -> API ACK -> state latch) verified across Desktop (1440x900), Tablet (768x1024), and Mobile (375x667).
3. **Ledger / Storage Layer (Database Synchronization)**: Centralized single-source-of-truth clearing against PostgreSQL with strict transactional boundaries and referential integrity.

## 2. Multi-Role Workflow Choreography
1. **Customer**: Browses catalogue, selects branch, configures customization, places COD order.
2. **Planner**: Inspects incoming queue, validates slot cutoff, assigns branch fulfillment.
3. **Branch Staff / Kitchen**: Acknowledges order, updates inventory consumption, transitions status to `ready_for_pickup`.
4. **Delivery Partner**: Accepts dispatch notification, verifies pickup OTP at branch, navigates to customer.
5. **Customer & Delivery Partner**: Delivery completion verified via delivery OTP; cash collected.
6. **Cash Settlement**: Delivery Partner remits cash to Branch Manager with till acknowledgement and zero variance.
