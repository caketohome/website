# Forensic System-Wide Debugging, 404 Investigation & Synchronization Architecture

## 1. Analogy: Telecom Signaling & Distributed Ledger Reconciliation
In telecommunications signaling (SS7/SIP) and ATM transaction networks, failures are categorized into three orthogonal layers:
1. **Routing Layer (404/SIP 404 Not Found)**: The route table has stale URI maps, dial-plan prefix mismatches, or inverted gateway rewrites.
2. **Session / Signaling Layer (RBAC/Controls)**: Inappropriate call-admission controls, session hijacking, or silent state dropping where a switch toggles locally but network signaling never acknowledges.
3. **Ledger / Storage Layer (Database Synchronization)**: Split-brain databases where branches hold un-replicated local counters, creating discrepancies with the central clearinghouse.

By mapping CakeToHome ERP to this three-layer signaling model:
- Browser route discovery maps to dial-plan verification.
- Interactive controls map to two-phase commit signaling (UI intent -> API ACK -> state latch).
- Entity synchronization (Branches, Products, Orders) maps to centralized single-source-of-truth clearing against PostgreSQL.

## 3. Systematic Execution Plan

### A. Routing & 404 Elimination
- Inventory all App Router pages: `(store)`, `(checkout)`, `dashboard`, `account`, and `api/v1/[...path]`.
- Fix route shadowing in `frontend/src/middleware.ts` where non-admin staff (`FINANCE_CONTROLLER`, `PLANNER`, `DELIVERY_MANAGER`) are improperly redirected to `/account` or denied entry.
- Audit Next.js route collisions between `api/v1/[...path]/route.ts` and explicit endpoints in `api/v1/admin/[...path]/route.ts`.
- Ensure canonical 404 responses occur ONLY for truly nonexistent resources, not valid roles or parameters.

### B. UI Controls & Interactive State Toggles
- Instrument every rendered switch, button, form, and modal selector.
- Enforce the 2-phase state latch: on toggle/click, verify the outgoing mutation request, assert server response HTTP 200/201, verify PostgreSQL row update, and confirm UI reflects state after hard page refresh.

### C. 9-Role E2E Verification
- Define isolated auth sessions for: Super Admin, Internal Admin, Finance Controller, Branch Manager, Branch Staff, Delivery Partner, Delivery Manager, Planner, Customer.
- Verify role landing pages, navigation authorization, branch isolation (`branch_id` scoping), and partner isolation (`delivery_partner_id`).

### D. PostgreSQL Source-of-Truth Entity Synchronization
- **Branches**: Verify branch CRUD, active status, city linkage via `public.city.id`, and branch inventory filtering.
- **Products**: Verify SKU uniqueness, Tax Master assignment, branch-level stock movement, and storefront visibility.
- **Orders**: Verify order lifecycle transitions (`pending` -> `confirmed` -> `preparing` -> `ready_for_pickup` -> `dispatched` -> `delivered`), line item pricing snapshots, and tax snapshots.
- **Financial Balance**: Preserve double-entry equilibrium ($\sum Dr \equiv \sum Cr = ₹14,625.00$), isolated accounts 1111/1114/1122/1121, and quarantined invoices 31-35.
