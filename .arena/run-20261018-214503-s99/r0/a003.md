# Decomposed Forensic Debugging & Database Synchronization Architecture

## 1. Sub-Problem Decomposition & Seam Analysis
We decompose this enterprise ERP challenge into five strictly bounded sub-problems:
- **Sub-Problem 1: App Router & Route Registry Integrity** (Entry seam: Next.js routing, middleware route guards, proxy rewrites, dynamic segment parsing).
- **Sub-Problem 2: UI Control Interactivity & State Binding** (Client seam: React component event handlers, optimistic mutation, rollback, revalidation).
- **Sub-Problem 3: Multi-Role Authorization & Isolation** (Security seam: Cookie session tokens, role claims, branch tenancy scoping, API route protection).
- **Sub-Problem 4: Relational Database Synchronization** (Data seam: PostgreSQL foreign key constraints, join conditions, schema indexes, transactional boundaries).
- **Sub-Problem 5: Financial Equilibrium & Invariant Protection** (Audit seam: Double-entry ledger reconciliation, Tax Master immutability, cash custody settlement).

## 2. Explicit Trade-Offs Matrix
1. **Trade-off: Fast Client Optimistic UI vs Strict Pessimistic Confirmation**
   - *Choice*: Pessimistic UI confirmation with loading spinners on financial/status transitions; optimistic UI for display toggles with automatic rollback on error.
   - *What we give up*: Instantaneous perceived click speed on checkout and order fulfillment in exchange for zero phantom successes.
2. **Trade-off: Central Catch-All API Handler vs Dedicated Route Handlers**
   - *Choice*: Maintain `api/v1/[...path]/route.ts` as an authoritative dispatcher, but ensure strict route pattern matching and fail-closed 404 responses for unknown endpoints.
   - *What we give up*: File-system-based routing simplicity in exchange for unified middleware token extraction, centralized logging, and consistent error envelopes.
3. **Trade-off: Deep Seed Data Reset vs Preserving Existing PostgreSQL State**
   - *Choice*: Strict preservation of existing database state; zero destructive migrations; isolated test fixtures with targeted cleanup.
   - *What we give up*: The convenience of a clean blank-slate test run in exchange for guaranteed protection of production and staging financial ledgers.
