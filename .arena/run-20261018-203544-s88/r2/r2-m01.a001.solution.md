# Final Champion Solution a001: Forensic 404 Investigation & Control Verification Protocol

## 1. Inversion Analysis: Preventing Audit Failures
1. **False Route 200s via SPA Fallback**: Next.js App Router might return HTTP 200 with an empty container or client-side redirect. We assert DOM content (no 404 header, present containers) and monitor all network responses.
2. **Untracked Client Navigation 404s**: Intercept all background fetch and RSC requests using Playwright's `page.on('response')`.
3. **Superficial Control Inventory**: Buttons inspected only via static AST parsing are rejected; every interactive control is clicked/triggered in real Chromium sessions.
4. **Relational Schema Invariants**: Respect `public.branch` schema by joining `public.city c ON c.id = branch.city_id` for state resolution.
5. **Financial Boundaries**: Strict enforcement of $\sum Dr \equiv \sum Cr = ₹14,625.00$; preserve quarantined invoices 31-35.

## 2. Tri-Stage Verification Pipeline
Every feature and control must satisfy three gates:
- **Gate 1 (Browser UI)**: Real Chromium interaction (click, type, toggle) via Playwright on `http://localhost:3001`.
- **Gate 2 (Gateway / Network)**: HTTP request intercepted, verifying method, URL, status code (200 OK vs 404), and JSON payload.
- **Gate 3 (PostgreSQL Persistence)**: Independent direct query on Supabase PostgreSQL (`aws-1-ap-south-1.pooler.supabase.com:6543/postgres`) confirming the row mutation.
