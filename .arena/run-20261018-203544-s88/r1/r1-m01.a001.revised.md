# Revised Solution a001: Forensic 404 Investigation & Control Verification Protocol

## 1. Inversion Analysis: Preventing Audit Failure
1. **False Route 200s via SPA Fallback**: Next.js App Router might return HTTP 200 with an empty container or client-side redirect. Prevention: Check DOM content for 404 text, missing root container, alongside network response inspection.
2. **Untracked Client Navigation 404s**: Links clicked via Next.js client router trigger `_rsc` fetch requests. Prevention: Hook `page.on('response')` to catch all status >= 400.
3. **Superficial Control Inventory**: Buttons inspected only via AST parsing without checking disabled state or real event triggers. Prevention: Playwright DOM crawler that triggers events and inspects network/DB changes.
4. **Relational Schema Nuances**: `public.branch` has no direct `state` column. Prevention: Always join `public.city c ON c.id = branch.city_id` or query `branch.metadata->>'state'` for state/tax determinations.
5. **Breach of Financial Boundaries**: Accidentally balancing accounts 1114/1122 or altering quarantined invoices 31-35. Prevention: Enforce read-only verification of accounting baseline ($\sum Dr \equiv \sum Cr = ₹14,625.00$).

## 3. Playwright Automation Architecture
- Node.js Playwright script targeting `http://localhost:3001`.
- Intercepts all network requests via `page.on('response')`, flagging non-200 responses.
- Generates `COMPLETE_ROUTE_404_LEDGER.md` and `COMPLETE_INTERACTIVE_CONTROL_LEDGER.md`.
- Asserts database mutations in Supabase PostgreSQL directly.
