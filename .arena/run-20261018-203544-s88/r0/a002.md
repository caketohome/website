# Solution a002: Enterprise-Grade Forensic Audit & Completeness Matrix

## 1. Open Questions First: Resolving Ambiguities
Before executing tests, we resolve architectural ambiguities in CakeToHome ERP:
1. **Role Context Definition**: Are roles stored in JWT session claims or queried dynamically per request from `public.users`? *Resolution*: Inspected `src/lib/auth.ts` and `api-engine.ts` - JWT carries `role`, but API middleware queries database permissions for privileged operations.
2. **Dashboard Architecture: Tab-based vs Distinct Route-based**: Why do `/dashboard/shop` and `/dashboard/delivery-partner` exist as distinct Next.js pages while admin features use `/dashboard?tab=<tab_name>`? *Resolution*: The ERP uses a hybrid model. Specialized role portals (`/dashboard/shop`, `/dashboard/delivery-partner`) have dedicated route trees, whereas administrative functions are unified under `/dashboard?tab=*` driven by dynamic tabs. Both must be audited.
3. **Database Branch State Column Gotcha**: Why did previous integration tests fail on `branch.state`? *Resolution*: Confirmed `public.branch` has no direct `state` column. It stores branch state either in `metadata->>'state'` or via relational join to `public.city c ON c.id = branch.city_id (c.state)`. All forensic queries must use this join.

## 2. ERP Analogy: Multi-Tiered Enterprise Control Framework
Just as SAP ECC/S4HANA segregates transactions into UI (SAP GUI / Fiori), Gateway (OData/RFC), and Database (ABAP Dictionary / HANA tables), CakeToHome ERP segregates into:
- **Presentation Tier**: Next.js 14 App Router (RSC, Client Components, Lucide Icons, Radix UI primitives).
- **Gateway Tier**: Next.js Route Handlers (`src/app/api/v1/[...path]/route.ts`) and Admin Route Handlers (`src/app/api/v1/admin/[...path]/route.ts`).
- **Domain Service Tier**: `src/lib/services/*.ts` (Inventory, Order, Accounting, Delivery).
- **Persistence Tier**: Supabase PostgreSQL 17.6 (Schema `public`).

## 3. Exhaustive 9-Role Coverage Plan
1. **Super Admin**: Audit system settings, user management, audit logs, global configuration, branch assignment.
2. **Admin**: Audit full operational dashboard (orders, catalog, inventory, customers, marketing, discounts, settings).
3. **Inventory Manager**: Audit stock levels, batch tracking, warehouse transfers, reorder thresholds, write-offs.
4. **Delivery Partner / Driver**: Audit `/dashboard/delivery-partner`, task assignment, GPS check-in, delivery proof upload, status transitions (Dispatched -> In Transit -> Delivered).
5. **Shop / Vendor Manager**: Audit `/dashboard/shop`, product catalog, order acceptance, preparation status, vendor payouts.
6. **Finance / Accounts Manager**: Audit chart of accounts, journal entries, AR/AP, tax reports, reconciliations, invoice auditing (quarantine 31-35).
7. **Customer Support**: Audit ticket resolution, order modification, customer history, refund initiation.
8. **Customer**: Audit storefront (`/`), product details (`/product/*`), cart, checkout (`/checkout`), customer account (`/account`), order history.
9. **Guest / Anonymous**: Audit catalog browsing, search, add to cart, guest checkout restrictions, login prompts.
