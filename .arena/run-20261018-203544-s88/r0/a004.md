# Solution a004: First Principles Route Forensics & Edge-Case Centric QA

## 1. First-Principles Decomposition of Route Resolution in Next.js 14
A route in Next.js 14 App Router can fail with 404 under 4 exact theoretical mechanisms:
1. **Static File Absence**: No matching `page.tsx` or `route.ts` exists in the filesystem hierarchy for the requested URI.
2. **Dynamic Segment Fallthrough Failure**: An optional or required catch-all (`[...path]`) matches the directory, but the runtime route handler lacks an `export async function GET/POST` for the requested HTTP verb, or returns an explicit `new NextResponse(null, { status: 404 })`.
3. **Client-Side Synthetic 404**: The server returns 200 with an App Router `not-found.tsx` component because `notFound()` from `next/navigation` was thrown by a server component (e.g. invalid item ID).
4. **Client-Side Hydration & Routing Desync**: A client component renders an `<a>` or `<button>` with an invalid `href` or unhandled state machine transition.

## 2. Exhaustive Edge Cases First
Before happy-path flows, we probe edge cases that standard audits overlook:
1. **Unauthenticated Access to Protected Dashboards**:
   - Accessing `/dashboard`, `/dashboard/shop`, `/dashboard/delivery-partner` without JWT cookies.
   - *Expected*: Immediate 307 redirect to `/auth/login` or clean 401 response; NOT unhandled 500 or broken blank screen.
2. **Role Privilege Escalation Boundaries**:
   - Accessing `/dashboard?tab=accounting` or `/dashboard?tab=system` as a Storefront Customer or Delivery Driver.
   - *Expected*: 403 Forbidden with user-friendly error or redirect; NOT exposure of restricted admin UI or unhandled 404.
3. **Empty State & Malformed Inputs in Interactive Controls**:
   - Submitting forms with empty required fields, negative quantities, special unicode characters, SQL injection strings.
   - *Expected*: Client-side Zod validation errors without network failure or 500 crash.
4. **Concurrent Order / Inventory Contention**:
   - Modifying stock simultaneously or accepting an order already cancelled.
   - *Expected*: Pessimistic or optimistic locking in Postgres with graceful UI feedback.

## 3. Systematic Discovery & Verification Workflow
1. **DOM Tree Crawl & Link Extraction**:
   - Recursively parse all rendered routes starting from `/`, `/auth/login`, and `/dashboard`.
   - Extract all clickable targets: `button`, `a[href]`, `[role="button"]`, `input[type="submit"]`, `select`.
2. **Automated Role Session Matrix**:
   - Generate test JWTs for all 9 defined roles.
   - Launch Chromium sessions for each role and visit all extracted URLs.
3. **Network Response Auditing**:
   - Monitor every XHR/Fetch request, logging URL, method, status, response time, and payload.
   - Categorize all non-200 responses.
4. **Fix Validation in Supabase PostgreSQL**:
   - For every mutation, assert state change in database.
   - Generate `COMPLETE_ROUTE_404_LEDGER.md` and `COMPLETE_INTERACTIVE_CONTROL_LEDGER.md`.
