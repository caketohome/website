# Solution a003: Multi-Expert Forensic Architecture & Structured Ledgers

## 1. Expert Panel Evaluation
Three senior technical specialists audited the architecture and task requirements:

### Panelist A: Principal Next.js & Web Architect
- **Observation**: Next.js 14 App Router's route resolution prioritizes exact folder matches over catch-alls (`[...path]`). If an exact folder exists without all subroute methods (e.g. `src/app/api/v1/admin` had an index or subset), any unhandled subroutes fail with 404 instead of falling through to `src/app/api/v1/[...path]`.
- **Finding**: Having both `src/app/api/v1/[...path]` and `src/app/api/v1/admin/[...path]` resolved the earlier shadowing, but now the internal dispatcher in `src/app/api/v1/admin/[...path]/route.ts` must exhaustively map all admin sub-resources (reports, accounting, inventory, customers, branches).
- **Trade-off**: Dynamic dispatcher vs distinct route files. Dynamic dispatcher minimizes file proliferation and allows unified error handling and authentication middleware, but requires strict switch/case path matching.

### Panelist B: Lead Chromium & Browser QA Automation Engineer
- **Observation**: Synthetic API tests (using node `fetch`) can verify endpoints, but they miss client-side routing bugs, Hydration errors, React state unmounts, unattached `onClick` listeners, disabled button states, and CSS pointer-events blocking clicks.
- **Finding**: Every role must be launched in Chromium using Playwright with full network request/response logging, console error interception, and interactive DOM event firing.
- **Trade-off**: Headless Chromium execution takes more execution time than pure curl/unit scripts, but is strictly required to fulfill the mission's "Browser-First Forensics" mandate.

### Panelist C: Financial Systems & Compliance Auditor
- **Observation**: ERP mutations must preserve ledger equilibrium. The current double-entry sum is verified at $\sum Dr \equiv \sum Cr = ₹14,625.00$ with diff ₹0.00.
- **Mandate**: Quarantined invoices 31–35 and negative balances in accounts 1114/1122 must remain untouched without explicit controller authorization. Automated testing of accounting controls must use safe sandboxed test records with rollback or designated testing accounts.

## 2. Restructured Ledger Specifications

### Ledger A: COMPLETE_ROUTE_404_LEDGER.md Schema
- `Route Path`: e.g., `/api/v1/admin/reports/ar/invoices` or `/dashboard?tab=tax`
- `Component / Page`: Source file responsible
- `HTTP Method`: GET / POST / PUT / DELETE
- `Observed Status`: 200 / 404 / 403 / 500
- `Root Cause`: Missing Next.js handler, client link typo, route collision, missing query param
- `Remediation Plan`: Exact file and line to patch
- `Verification Evidence`: HTTP status after fix and Playwright network response log

### Ledger B: COMPLETE_INTERACTIVE_CONTROL_LEDGER.md Schema
- `Page / Tab`: e.g., `/dashboard?tab=orders`
- `Control Type`: Button / Switch / Dropdown / Form / Modal
- `Selector / Label`: e.g., `button:has-text("Add Product")`
- `Assigned Role`: Admin / Super Admin / Inventory / etc.
- `Observed Action`: Click / Submit / Toggle
- `Network Call`: URL and HTTP status triggered
- `DB Verification`: Exact PostgreSQL table and row mutated (or N/A for UI-only control)

## 3. Explicit Trade-Offs Settle-Out
- **Traceability vs Speed**: We choose 100% granular traceability in Markdown ledgers over rushed summary statements.
- **Safe Test Isolation vs Live Data Pollution**: We create dedicated test entities with unique UUID prefixes (e.g. `audit-test-*`) to prevent corrupting existing customer or financial records.
