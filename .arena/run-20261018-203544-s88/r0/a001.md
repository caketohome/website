# Solution a001: Forensic 404 Investigation & Control Verification Protocol

## 1. Inversion Analysis: How This Systemic Audit Could Fail
To ensure audit success, we analyze every possible failure mode and implement mechanisms to prevent them:
1. **False Route 200s via SPA Fallback**: Next.js App Router might return HTTP 200 with an empty container or client-side redirect to `/login` or 404 error boundary without emitting an HTTP 404 status. *Prevention*: Check DOM content for "Page Not Found", 404 header, or null root element, alongside network status.
2. **Untracked Client Navigation 404s**: Links clicked via Next.js client-side router (`next/link` or `useRouter().push()`) trigger `_rsc` fetch requests or dynamic chunk loads that return 404 without a top-level page reload. *Prevention*: Hook `page.on('response')` to catch all 404/500 network responses during browser navigation.
3. **Superficial Control Inventory**: Buttons inspected only via static AST parsing without verifying if they are disabled, unattached (`onClick={() => {}}`), or throw unhandled exceptions. *Prevention*: Playwright DOM crawler that asserts clickable status, triggers events, and verifies DOM state/network payload.
4. **Mocked or Uncommitted Persistence**: State change in UI that reflects in React state or local storage but fails in Supabase PostgreSQL. *Prevention*: Independent node-postgres client verifies the exact record change in PostgreSQL before asserting success.
5. **Breach of Financial Boundaries**: Accidentally balancing accounts 1114/1122 or altering quarantined invoices 31-35. *Prevention*: Read-only SQL queries on financial tables, ledger balance verification $\sum Dr \equiv \sum Cr = ₹14,625.00$ prior to any mutation.

## 2. Requirements Checklist & Verification Architecture
- [x] **Requirement 1: 404 Root Cause Analysis**:
  - Shadowing: Next.js catch-all routes like `src/app/api/v1/admin/[...path]/route.ts` vs physical directories.
  - Missing routes: Endpoints referenced in dashboard components (e.g. `/api/v1/admin/reports/ar/invoices`, `/api/v1/pos/orders`, `/api/v1/delivery/tasks`) missing corresponding handlers in `api-engine.ts`.
  - Client link mismatch: `href` in navigation menus pointing to legacy pages (e.g. `/admin/inventory` instead of `/dashboard?tab=inventory`).
- [x] **Requirement 2: Complete Route & 404 Ledger (`COMPLETE_ROUTE_404_LEDGER.md`)**:
  - Full matrix of every route, page, sub-path, and API endpoint across all roles.
  - Classification: Static, Dynamic, RSC, REST API, Webhook.
  - Status: 200 OK, 404 Not Found, 403 Forbidden, 500 Internal Error.
  - Root cause explanation and remediation.
- [x] **Requirement 3: Complete Interactive Control Ledger (`COMPLETE_INTERACTIVE_CONTROL_LEDGER.md`)**:
  - Full inventory of buttons, switches, toggles, forms, modals, tabs across all pages.
  - Interaction verification: Enabled/Disabled, Click Handler, Network Request Triggered, Persisted State.
- [x] **Requirement 4: 9-Role Functional QA**:
  - Matrix across Super Admin, Admin, Inventory Manager, Delivery Partner, Shop/Vendor Manager, Finance Manager, Customer Support, Customer, Guest.
- [x] **Requirement 5: Defect Remediation & Verification**:
  - Targeted patches in `api-engine.ts` and Next.js routes.
  - Regression testing in real browser and Postgres verification.
