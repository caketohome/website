# Proposal a001: Probabilistic Hostile-Break Hardening for Statutory Invoicing

## 1. Vulnerability Analysis: 5 Hostile Scenarios & Failure Probability

We analyze the current `DeliveryInvoicingService.generateInvoiceOnDelivery` against 5 hostile scenarios:

1. **Scenario 1: Database Connection Refused / Pool Drained**
   - *Current Code*: Lines 383-401 catch database error in `seqCheckErr`, log `console.error`, and proceed to line 403. Later at line 564, it attempts transaction.
   - *Risk*: High. Swallowing the check error violates fail-closed security.
   - *Fix*: The catch block MUST return `{ success: false, error: "Database sequence verification failed: ...", code: "INVOICE_SEQUENCE_VERIFICATION_FAILED" }`.

2. **Scenario 2: Prefix Binding Collision (CGST Rule 46)**
   - *Current Code*: Queries `invoice_sequence WHERE prefix = $1 AND fiscal_year = $2`. If bound to another GSTIN, returns `INVOICE_SERIES_PREFIX_CONFLICT`.
   - *Risk*: Low. Verified to work, but needs to cover PostgreSQL allocator `AMBIGUOUS_GSTIN_SEQUENCE_SCOPE` in transaction catch.
   - *Fix*: Map PostgreSQL allocator exception `AMBIGUOUS_GSTIN_SEQUENCE_SCOPE` directly to `INVOICE_SERIES_PREFIX_CONFLICT`.

3. **Scenario 3: Missing, Blank, or Malformed Prefix**
   - *Current Code*: Falls back to `"CTH"` silently. If user passes `""` or `"   "`, it becomes `"CTH"`, silently picking the conflicting prefix!
   - *Risk*: High. Silent fallback to conflicting prefix.
   - *Fix*: Validate `cleanPrefix = (prefix || "").trim()`. If empty or regex `!/^[A-Za-z0-9\-_]{1,16}$/`, return `{ success: false, error: "...", code: "INVOICE_PREFIX_INVALID" }`.

4. **Scenario 4: Concurrent Duplicate Allocation Requests**
   - *Current Code*: Covered by PostgreSQL advisory lock `pg_advisory_xact_lock` and idempotency check.
   - *Fix*: Assert idempotency returns existing invoice without incrementing sequence.

5. **Scenario 5: Unregistered Series for Active GSTIN**
   - *Current Code*: If sequence doesn't exist yet, it inserts with `last_seq = 1`.
   - *Risk*: Medium. Active GSTIN `29AABCC1234F1Z5` must NOT autonomously create sequence under `"CTH"`.
   - *Fix*: Block `"CTH"` prefix explicitly for active GSTIN `29AABCC1234F1Z5` until CA signoff.

## 2. Concrete Implementation

In `frontend/src/lib/services/delivery-invoicing.service.ts`:
- Validate prefix format (alphanumeric, hyphens/underscores, 1-16 chars).
- Fail-closed try/catch around sequence check.
- Map allocator exception in transaction to `INVOICE_SERIES_PREFIX_CONFLICT`.
- Retain order and payment records when invoice allocation is blocked.
