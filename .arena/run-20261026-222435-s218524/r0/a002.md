# Proposal a002: Working Backwards & Complete 8-Scenario Safeguard

## 1. Target End-State Specification
A robust statutory invoicing system guarantees:
1. Every invoice allocated adheres strictly to CGST Rule 46 (unique 16-char series per GSTIN per fiscal year).
2. Unverifiable states (database timeouts, unreachable pool, permission errors) FAIL CLOSED before any transaction begins.
3. Order and payment workflows are cleanly decoupled: an invoicing blocker NEVER rolls back customer order or payment data.
4. All errors are structured (`INVOICE_SERIES_PREFIX_CONFLICT`, `INVOICE_SEQUENCE_VERIFICATION_FAILED`, `INVOICE_PREFIX_INVALID`) with sanitized messages containing zero credentials.

## 2. 8-Scenario Matrix Implementation
1. Same-GSTIN series: Allowed.
2. Conflicting-GSTIN series: Returns `INVOICE_SERIES_PREFIX_CONFLICT`.
3. No existing sequence: If prefix is not registered or conflicts, fails closed.
4. Database down: Returns `INVOICE_SEQUENCE_VERIFICATION_FAILED`.
5. DB Query error: Returns `INVOICE_SEQUENCE_VERIFICATION_FAILED`.
6. Missing/invalid prefix: Returns `INVOICE_PREFIX_INVALID`.
7. Allocator rejection: Returns `INVOICE_TRANSACTION_FAILED` / `INVOICE_SERIES_PREFIX_CONFLICT`.
8. Concurrency: Advisory transaction lock ensures zero sequence gaps or duplicates.

## 3. Order Preservation
In `order-lifecycle-service.ts`, `generateInvoiceOnDelivery` failure logs a non-blocking warning, leaving order status intact as delivered and order record untouched in PostgreSQL `"order"`.
