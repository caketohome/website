## 1. Phase 2 Verification & Changes

### Root Cause Analysis
* `listOccasions()` in `frontend/src/lib/data/catalog.ts` was previously executing `GROUP BY 1, 2, 3, 4, 5, 6` where columns 5 and 6 were `thumbnail as image` and `thumbnail as cover_image`. Because multiple products with occasion `"Birthday"` possessed distinct thumbnails, the query emitted 6 duplicate rows, each having `id: "occ_birthday"`.
* When `PageRenderer` (`frontend/src/components/store/cms/page-renderer.tsx`) rendered the occasions section, `key={occ.id || occ.slug}` evaluated to `"occ_birthday"` across multiple sibling elements, triggering the React console warning:
  `Warning: Encountered two children with the same key, 'occ_birthday'.`

### Surgical Fix Applied
1. **`frontend/src/lib/data/catalog.ts`**:
   * Updated `listOccasions()` SQL query to aggregate thumbnails using `MAX(thumbnail) as image, MAX(thumbnail) as cover_image` and group strictly by the 4 identity columns (`GROUP BY 1, 2, 3, 4`).
   * Verified via `node scratch/test_occasion_query.js`: returned rows collapsed from 6 duplicates down to 1 distinct record with count = 6, and 0 duplicate IDs.
2. **`frontend/src/components/store/cms/page-renderer.tsx`**:
   * Added defensive client/renderer identity deduplication on `displayOccasions`.
   * Formatted card keys with stable composite identifier: `cardKey = "occ-" + (section.id || "sec") + "-" + (occ.id || occ.slug || "item") + "-" + (occIdx ?? 0)`.
   * Applied `key={cardKey}` across all occasion styles (`scrapbook`, `coquette`, `tenebrism`, `japandi`, `glass`, `luxury`/default) and passed `idx` to mapper callbacks.
