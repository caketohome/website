## 7. Forensic Root-Cause Analysis of the 10 User-Identified Issues

### Issue 1: Admin CRM Page Contrast & Generic Styling
- **Root Cause:** In `crm-panel.tsx`, filter dropdowns use un-themed native classes with weak borders (`border-neutral-200`), table hover states use generic grey `hover:bg-neutral-50/80`, and quick action icons use arbitrary rose tints (`text-rose-700 hover:bg-rose-100`). In `globals.css`, global input overrides (`color: #07090E !important; background-color: #FFFFFF !important`) conflict with dark mode containers (`bg-ui-bg-base: #07090E`), causing low contrast.
- **Remedy:** Apply cohesive Patisserie Navy (`#1D2F5D`), Patisserie Gold (`#D4AF37`), slate borders, and WCAG AA contrast rules to the entire CRM panel, filters, customer cards, and profile drawer. Replace hardcoded score `85/100` fallback with truthful metadata representation.

### Issue 2: Content/Page Builder Horizontal Overflow
- **Root Cause:** In `page-configurator.tsx`:
  1. The sticky top toolbar (`lg:flex-row`) hosts the page selector (~300px), 4 viewport buttons (~380px), and 8 action buttons (`sm:flex-nowrap`, ~750px), requiring > 1400px width. At viewports 768px, 1024px, 1100px, and 1280px, it forces document-level overflow.
  2. The Center Panel preview canvas inner container is hardcoded to `w-[1100px]` when `canvasDevice === "desktop"`, overflowing its 6-column grid wrapper (`col-span-12 lg:col-span-6`).
- **Remedy:** Implement responsive wrapping and scrolling in the toolbar; scale or containerize the preview canvas viewport using CSS `max-w-full` / `scale` / `overflow-x-auto` with zero document-level horizontal scroll (`document.scrollWidth === document.clientWidth`).

### Issue 3: Page Builder Controls Washed Out / Unreadable
- **Root Cause:** In `page-configurator.tsx`, `section-config-editor.tsx`, and `announcement-bar-editor.tsx`, controls use Medusa UI `Select`, `Input`, and native form elements with ambiguous classes, washed-out placeholder colors, and default white-on-white or gray-on-gray borders.
- **Remedy:** Style all Page Builder controls with high-contrast text (`#07090E` in light, `#F4F5F8` in dark), solid background tokens (`#FFFFFF` in light, `#0D152B` in dark), visible borders (`#CBD5E1` / `#2A4380`), clear focus rings (`#D4AF37`), and readable typography.

### Issue 4: Publish Button Blank / Loading / Unreliable
- **Root Cause:** In `page-configurator.tsx`:
  1. `Button` uses `@medusajs/ui`'s `isLoading={publishing}`, which replaces children with an unstyled or low-contrast spinner, rendering the button blank.
  2. `handlePublish` triggers `await loadAll(...)` which executes `setLoading(true)`, tearing down the entire Page Builder and replacing it with a full-screen skeleton flash. If background queries lag, it appears stuck/blank.
  3. `publishCmsPage` already returns the updated, published page record directly from PostgreSQL (`res.page`).
- **Remedy:** Prevent full-screen `setLoading(true)` on save/publish; immediately update `editingPage` with `res.page`; render an explicit spinner with a clear, readable text label (`"Publishing to PostgreSQL..."`); ensure the button updates to `"All Changes Saved & Published"` with a verified timestamp.

### Issue 5 & 6: Theme / Colors Inconsistent & Fonts Not Consistently Applied
- **Root Cause:** Residual rose/pink defaults (`#e11d48`, `#FF4D6D`, `bg-rose-600`) persist in `page-renderer.tsx` (e.g. comparison table, CTA fallbacks), `page-configurator.tsx` (e.g. `blankPage()`), `manifest.json`, and dynamic section fallbacks. Headings and cards in dynamic sections occasionally fall back to system fonts rather than Playfair serif or Inter sans.
- **Remedy:** Centralize all theme CSS variables into `--theme-primary: #1D2F5D`, `--theme-accent: #D4AF37`, `--theme-heading-font: var(--font-playfair)`, `--theme-body-font: var(--font-inter)`. Purge residual unapproved rose colors from default button states.

### Issue 7 & 8: Category & Product Cards Generic / Competing "Order" Button
- **Root Cause:** In `frontend/src/app/(store)/city/[slug]/page.tsx` and `frontend/src/components/store/cms/page-renderer.tsx` (comparison table), isolated "Order Now" buttons exist. In `search/page.tsx`, product cards use a generic un-themed layout instead of the luxury editorial `ProductCard`.
- **Remedy:** Ensure every product card is 100% clickable to PDP via an accessible stretched link; remove any competing "Order" buttons; ensure category cards link to the authoritative category route; standardize luxury editorial styling across all listings.

### Issue 9: Mobile Header Issues

- **Remedy:** Confirm header responsiveness at 320px and 375px with real browser testing; ensure zero overlap between logo, search, location selector, cart, and profile.
