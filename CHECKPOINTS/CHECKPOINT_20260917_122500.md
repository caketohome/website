## Root Cause Summary
1. **Occasion Card URL Generation:** In `page-renderer.tsx` and `occasions-grid-editor.tsx`, manual occasion cards and default fallbacks were constructing URLs pointing to `/products?occasion=:slug` instead of the canonical `/occasions/:slug` route. In addition, the PostgreSQL CMS page `cmspg_home` stored manual occasion card entries with `url: "/products?occasion=..."`.
2. **Products Catalog Search Parameter Parsing:** The `/products` route (`products/page.tsx` and `products-catalog-client.tsx`) and `ProductRepository.listProducts` did not process the `occasion` / `occasion_id` filter parameter, completely ignoring it and showing all products without occasion filtering.
3. **Product Occasion Data & Culinary Matching:** PostgreSQL products only had `["occ_birthday"]` populated; other occasions had 0 matching products in the DB. In `ApiEngine.getOccasionProducts()`, matching was strictly limited to exact slug/ID equality without case normalization or multi-occasion taxonomy fallback, causing non-birthday occasion routes to appear empty or fall back to generic listings.
4. **Category Card Route Consistency:** In `page-renderer.tsx`, category cards were generating links using `/products?category=...` rather than the dedicated `/category/:slug` route.
