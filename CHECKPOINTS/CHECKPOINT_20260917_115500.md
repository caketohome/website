Root cause:
1. Occasion Cards in Storefront & CMS (page-renderer.tsx & occasions-grid-editor.tsx):
   - In page-renderer.tsx (line 1859), occasion card links default to '/products?occasion=${occ.slug}' or use occ.url from CMS.
   - In occasions-grid-editor.tsx (lines 460-461), manual occasion cards are populated with url: '/products?occasion=${occ.slug}'.
   - In PostgreSQL cms_page ('cmspg_home'), existing manual_occasions cards have saved url: '/products?occasion=...'.
   - Thus, clicking any occasion card redirects to '/products' instead of the dedicated occasion route '/occasions/[slug]'.
2. Missing Occasion Filter on '/products' (products/page.tsx, products-catalog-client.tsx, ProductRepository.listProducts):
   - products/page.tsx does not parse 'searchParams.occasion'.
   - ProductRepository.listProducts has no WHERE condition for 'occasion' or 'occasion_id'.
   - ProductsCatalogClient has no state or UI handler for 'occasion' query parameter.
   - When a user lands on '/products?occasion=anniversary', the server completely ignores the parameter and returns all 18 products.
3. Incomplete Occasion Taxonomy in ApiEngine & Product Catalog:
   - In ApiEngine.migrateOccasions(), any product without an explicit occasion was forced into 'occ_birthday' only.
   - ApiEngine.getOccasionProducts() only checked strict occasion_ids array membership, returning 0 products for 'anniversary', 'wedding', 'engagement', 'valentines-day', etc.
   - Therefore, /occasions/anniversary, /occasions/wedding, etc. had 0 products returned.
4. Category Cards Navigation:
   - Category cards in page-renderer.tsx (line 1594) point to '/products?category=...'.
   - The dedicated route is '/category/[slug]', which renders CategoryClientPage and correctly filters by category.
